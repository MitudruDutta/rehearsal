The `rehearsal` command does everything the console does, from a terminal or a script. It is part of the
`rehearsal-kit` package. Commands print JSON, so you can pass the output to other tools.

```bash
pip install rehearsal-kit
rehearsal login
```

Without an installation, run any command through `uvx`: `uvx --from rehearsal-kit rehearsal login`.

The CLI uses the server and key that `rehearsal login` saved. The environment variables `REHEARSAL_URL` and
`REHEARSAL_API_KEY` take precedence, which is what a CI job uses. When a command fails, the CLI prints the
server's message and a hint: see [Errors](/reference/errors).

## Start

### rehearsal login

Sign in: approve this terminal in your browser, or paste an API key.

The terminal shows a confirmation code and opens the console. Check that the browser shows the same code, then choose **Approve**. The terminal receives a key with "Build and evaluate" access and saves it for your user only. See [Sign in and keys](/get-started/sign-in-and-keys).

```text
rehearsal login [--url <url>] [--with-key] [--no-browser]
```

| Argument | Default | Meaning |
|---|---|---|
| `--url <url>` |  | Rehearsal server (default: REHEARSAL_URL, the last server you signed in to, or https://rehearsalkit.xyz) |
| `--with-key` |  | Paste an API key instead of approving in the browser (servers, CI) |
| `--no-browser` |  | Print the approval link instead of opening a browser. |

```bash
rehearsal login --url https://rehearsal.example.com
```

### rehearsal autofix

Fix an agent in rounds, keep only versions that verify more, prove the best on held-out jobs.

This spends model budget for every rehearsal: rounds × (train and dev jobs) plus two versions on the held-out jobs, times `--repeats`. The answer shows the episode count. A version is kept only if it verifies more episodes without a new rule violation or false completion. See [Improve an agent](/guides/improve-an-agent).

<Cost>

This command spends model budget.

</Cost>

```text
rehearsal autofix <profile_id> <run_id> [--rounds <rounds>] [--repeats <repeats>] [--watch]
```

| Argument | Default | Meaning |
|---|---|---|
| `<profile_id>` | required | Agent profile id, from `rehearsal profiles list`. |
| `<run_id>` | required | A finished run that has finished train or dev episodes of this agent. |
| `--rounds <rounds>` | `3` | Proposals to try, 1 to 5. The loop stops early when every train and dev job passes. |
| `--repeats <repeats>` | `1` | Attempts at each job in every rehearsal, 1 to 5. |
| `--watch` |  | Stay attached, print each round, then print the result. |

```bash
rehearsal autofix <profile_id> <run_id> --rounds 3 --watch
```

The command prints a `job_id` and the most episodes the loop can run, then follows each round. The result names the best version and its held-out score next to the original's.

### rehearsal factory

Make a verified agent for a world: draft it, harden it, prove it on held-out jobs, package it.

This spends model budget for every rehearsal: (rounds + 1) × (train and dev jobs) plus two versions on the held-out jobs, times `--repeats`. The agent is drafted from the world, hardened by the fix loop and proved on held-out jobs. See [Make an agent](/guides/make-an-agent).

<Cost>

This command spends model budget.

</Cost>

```text
rehearsal factory <wv_id> [--name <name>] [--rounds <rounds>] [--repeats <repeats>] [--watch]
```

| Argument | Default | Meaning |
|---|---|---|
| `<wv_id>` | required | A published world version. |
| `--name <name>` |  | The agent's name: lowercase letters, digits and dashes. Default: the world's name followed by `-agent`. |
| `--rounds <rounds>` | `3` | Rounds of improvement, 1 to 5. The loop stops early when every train and dev job passes. |
| `--repeats <repeats>` | `1` | Attempts at each job in every rehearsal, 1 to 5. |
| `--watch` |  | Stay attached, print each phase, then print the result and the download command. |

```bash
rehearsal factory <wv_id> --name support-agent --rounds 3 --watch
```

It prints the job and the most episodes it can run, follows each phase, then prints the scores and the command that downloads the agent: a zip with agent.py, agent.json, PROOF.md and README.md.

### rehearsal gate

Pass or fail an agent change in CI: rehearse it, next to a baseline, and judge the result.

Made for CI: it spends model budget for each episode, like `eval`. Every flag of the check has a default that fails on a rule violation and on any regression against the baseline. See [Use Rehearsal in CI](/guides/use-rehearsal-in-ci).

<Cost>

This command spends model budget.

</Cost>

```text
rehearsal gate [<wv_id>] [--profile <profile>] [--prompt-file <prompt_file>] [--name <name>] [--baseline <baseline>] [--baseline-file <baseline_file>] [--split <split>]... [--repeats <repeats>] [--min-success <min_success>] [--max-violations <max_violations>] [--tolerance <tolerance>] [--budget <budget>] [--run <run>] [--timeout <timeout>] [--report <report>]
```

| Argument | Default | Meaning |
|---|---|---|
| `<wv_id>` |  | The published world version to rehearse on. Not needed with `--run`. |
| `--profile <profile>` |  | The agent profile to test. |
| `--prompt-file <prompt_file>` |  | Test a version of `--name` made from this instructions file. When the latest version with the same instructions exists, it is reused. |
| `--name <name>` |  | The agent's name, with `--prompt-file` or `--baseline-file`. |
| `--baseline <baseline>` |  | A profile to rehearse in the same run. The change may not do worse. |
| `--baseline-file <baseline_file>` |  | The baseline as an instructions file, for example the file on the main branch. |
| `--split <split>` |  | Which split to rehearse. Repeat for several. Default: every split. |
| `--repeats <repeats>` | `1` | Attempts at each job. |
| `--min-success <min_success>` |  | Fail below this verified success rate, from 0 to 1. |
| `--max-violations <max_violations>` |  | Fail above this many episodes with a rule violation. |
| `--tolerance <tolerance>` |  | How far below the baseline's success rate still passes, from 0 to 1. |
| `--budget <budget>` |  | Model spend in US dollars at which the run stops itself. |
| `--run <run>` |  | Judge this finished run instead of starting one. |
| `--timeout <timeout>` | `90` | Minutes to wait for the run. A run that does not finish in time exits with 2. |
| `--report <report>` |  | Append the Markdown report to this file, for example `$GITHUB_STEP_SUMMARY`. |

```bash
rehearsal gate <wv_id> --prompt-file agent/instructions.md --name support-agent --baseline-file main-instructions.md --min-success 0.6
```

It prints the run's progress, then a Markdown report, and exits 0 when the change passes, 1 when it fails, and 2 when the run did not finish.

```bash
rehearsal gate --run <run_id> --profile <profile_id> --baseline <profile_id> --report summary.md
```

Judges a finished run without starting a new one.

### rehearsal mcp

Run the MCP server for AI assistants (stdio; uses your rehearsal login).

AI assistants start this command themselves. See [AI assistants](/ai-assistants).

```text
rehearsal mcp
```

```bash
rehearsal mcp
```

The server talks over standard input and output, so it prints nothing in a terminal. It needs the mcp extra: `pip install 'rehearsal-kit[mcp]'`.

### rehearsal skill

Install the Rehearsal skill for Claude Code and other agents.

```text
rehearsal skill <action> [--dir <dir>]
```

| Argument | Default | Meaning |
|---|---|---|
| `<action>` | required | `install` copies the skill into a skills folder. `print` writes it to the terminal. One of: `install`, `print`. |
| `--dir <dir>` |  | Skills folder (default ~/.claude/skills) |

```bash
rehearsal skill install --dir ~/.claude/skills
```

## Run your own server

These commands run on the server, not against it. They need the server extra: `pip install 'rehearsal-kit[server]'`.

### rehearsal serve

<Label kind="self-hosted" /> Run the API and console.

```text
rehearsal serve [--host <host>] [--port <port>]
```

| Argument | Default | Meaning |
|---|---|---|
| `--host <host>` | `127.0.0.1` | Address to listen on. Use `0.0.0.0` only behind a proxy that adds HTTPS. |
| `--port <port>` | `7800` | Port to listen on. |

```bash
rehearsal serve --host 127.0.0.1 --port 7800
```

<Output>

```text
Rehearsal API on http://127.0.0.1:7800, database 127.0.0.1
```

</Output>

### rehearsal worker

<Label kind="self-hosted" /> Run a job worker.

Builds and evaluations run only while a worker is running. See [Install with Docker Compose](/self-hosting/install-with-docker-compose).

```text
rehearsal worker [--kinds <kinds>] [--once]
```

| Argument | Default | Meaning |
|---|---|---|
| `--kinds <kinds>` |  | Comma-separated job kinds. |
| `--once` |  | Exit when the queue is empty. |

```bash
rehearsal worker --kinds world_build
```

Without `--kinds`, the worker takes every kind of work: `world_build`, `world_validate`, `evaluation`, `improvement`, `dataset_export` and `bundle_export`.

### rehearsal bootstrap

<Label kind="self-hosted" /> Create an organisation, project, and admin API key.

Run it once on a new server. The key is shown once: save it.

```text
rehearsal bootstrap [--org <org>] [--project <project>]
```

| Argument | Default | Meaning |
|---|---|---|
| `--org <org>` | `Local` | Name of the organisation to create. |
| `--project <project>` | `default` | Name of the project to create in it. |

```bash
rehearsal bootstrap --org Acme --project default
```

<Output>

```text
project: prj_7f4a9532b99af3d2
admin API key (shown once): rh_1a2b3c4d_...
export REHEARSAL_API_KEY=rh_1a2b3c4d_...
```

</Output>

### rehearsal users

<Label kind="self-hosted" /> Console accounts (runs on the server).

The console needs a person's account. This command creates one in the project you name.

| Action | What it does |
|---|---|
| `rehearsal users add <email> [--name <name>] --project <project> [--role <role>] [--no-password]` | Give a person access to a project's organisation |

Arguments of `rehearsal users add`:

| Argument | Default | Meaning |
|---|---|---|
| `<email>` | required | The person's email address. They sign in to the console with it. |
| `--name <name>` |  | Display name. Without it, the part of the email before the @. |
| `--project <project>` | required | Project id, as printed by bootstrap. |
| `--role <role>` | `owner` | What the person may do in the organisation. One of: `owner`, `admin`, `member`. |
| `--no-password` |  | The person signs in with Google only. |

```bash
rehearsal users add you@example.com --project <project_id>
```

<Output>

```text
Password (10+ characters): 
Repeat: 
you@example.com can sign in to the console as owner of project prj_7f4a9532b99af3d2.
```

</Output>
